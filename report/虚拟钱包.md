## 接口详细说明

### 1. 获取钱包信息

**接口路径**: `GET /api/wallet/info`

**功能说明**: 获取当前用户的钱包信息，包括余额、VIP状态、透支额度等

**前端调用位置**:
- `elmclient/src/views/Wallet.vue` 第353行
- `elmclient/src/views/MyInformation.vue` 第517行

**请求头**:
```
Authorization: Bearer {token}
```

**请求参数**: 无

**响应格式**:
```json
{
  "success": true,
  "data": {
    "id": 1,
    "userId": 123,
    "balance": 1000.00,
    "isVip": true,
    "vipLevel": 2,
    "overdraftLimit": 500.00,
    "usedOverdraft": 100.00,
    "frozenAmount": 0.00
  },
  "message": "获取成功"
}
```

**字段说明**:
- `balance`: 账户余额（元）
- `isVip`: 是否为VIP用户
- `vipLevel`: VIP等级（1-3）
- `overdraftLimit`: 可透支总额度（元）
- `usedOverdraft`: 已使用透支金额（元）
- `frozenAmount`: 冻结金额（元）

**错误响应**:
- 404: 钱包不存在（前端会触发创建钱包流程）
```json
{
  "success": false,
  "message": "钱包不存在"
}
```

### 3. 获取充值/提现规则

**接口路径**: `GET /api/wallet/rules`

**功能说明**: 获取充值奖励率和提现手续费率等规则配置

**前端调用位置**:
- `elmclient/src/views/Wallet.vue` 第396行

**请求头**:
```
Authorization: Bearer {token}
```

**请求参数**: 无

**响应格式**:
```json
{
  "success": true,
  "data": {
    "rechargeRules": {
      "rewardRate": 0.1  // 充值奖励率，10% = 0.1
    },
    "withdrawRules": {
      "feeRate": 0.1  // 提现手续费率，10% = 0.1
    },
    "rulesText": "<p>1. 充值金额需大于0.01元</p><p>2. 充值奖励率：10%</p>..."  // 规则详细文本（HTML格式，可选）
  },
  "message": "获取成功"
}
```

**字段说明**:
- `rewardRate`: 充值奖励率（小数，如0.1表示10%）
- `feeRate`: 提现手续费率（小数，如0.1表示10%）
- `rulesText`: 规则详细文本，支持HTML格式，如果为空则前端使用默认文本

**注意**: 如果接口返回失败或没有`rulesText`，前端会使用默认规则文本（见 `Wallet.vue` 第210-217行和第236-242行）

### 4. 钱包充值

**接口路径**: `POST /api/wallet/recharge`

**功能说明**: 用户向钱包充值，充值成功后根据奖励率发放奖励

**前端调用位置**:
- `elmclient/src/views/Wallet.vue` 第423行

**请求头**:
```
Authorization: Bearer {token}
Content-Type: application/json
```

**请求体**:
```json
{
  "amount": 1000.00  // 充值金额（元）
}
```

**响应格式**:
```json
{
  "success": true,
  "data": {
    "transactionId": 12345,
    "rechargeAmount": 1000.00,
    "rewardAmount": 100.00,  // 奖励金额
    "finalBalance": 1100.00  // 充值后的余额
  },
  "message": "充值成功"
}
```

**业务逻辑**:
1. 验证充值金额 > 0.01
2. 计算奖励金额 = 充值金额 × 奖励率
3. 更新钱包余额 = 原余额 + 充值金额 + 奖励金额
4. 创建交易流水记录（类型：recharge）
5. 创建奖励流水记录（类型：reward）

**错误响应**:
```json
{
  "success": false,
  "message": "充值金额无效" // 或其他错误信息
}
```

### 5. 钱包提现

**接口路径**: `POST /api/wallet/withdraw`

**功能说明**: 用户从钱包提现，提现时会扣除手续费，并扣除之前获得的充值奖励

**前端调用位置**:
- `elmclient/src/views/Wallet.vue` 第451行

**请求头**:
```
Authorization: Bearer {token}
Content-Type: application/json
```

**请求体**:
```json
{
  "amount": 500.00  // 提现金额（元）
}
```

**响应格式**:
```json
{
  "success": true,
  "data": {
    "transactionId": 12346,
    "withdrawAmount": 500.00,
    "feeAmount": 50.00,  // 手续费
    "rewardDeduction": 50.00,  // 扣除的奖励金额
    "actualAmount": 400.00,  // 实际到账金额
    "finalBalance": 500.00  // 提现后的余额
  },
  "message": "提现成功"
}
```

**业务逻辑**:
1. 验证提现金额 > 0.01 且 <= 账户余额
2. 计算手续费 = 提现金额 × 手续费率
3. 计算需要扣除的奖励金额（根据充值奖励历史）
4. 实际扣除 = 提现金额 + 手续费 + 奖励扣除
5. 更新钱包余额 = 原余额 - 实际扣除
6. 创建交易流水记录（类型：withdraw）

**错误响应**:
```json
{
  "success": false,
  "message": "余额不足" // 或其他错误信息
}
```

### 6. 还款（透支）

**接口路径**: `POST /api/wallet/repay`

**功能说明**: 用户偿还透支金额，可以使用钱包余额或第三方支付

**前端调用位置**:
- `elmclient/src/views/Wallet.vue` 第476行

**请求头**:
```
Authorization: Bearer {token}
Content-Type: application/json
```

**请求体**:
```json
{
  "method": "wallet",  // 还款方式：wallet（钱包余额）或 thirdparty（第三方支付）
  "amount": 100.00  // 还款金额（元），通常等于usedOverdraft
}
```

**响应格式**:
```json
{
  "success": true,
  "data": {
    "transactionId": 12347,
    "repayAmount": 100.00,
    "finalBalance": 900.00,  // 还款后的余额（如果使用钱包余额）
    "remainingOverdraft": 0.00  // 剩余透支金额
  },
  "message": "还款成功"
}
```

**业务逻辑**:
1. 验证还款金额 <= 已使用透支金额
2. 如果使用钱包余额还款：
   - 验证钱包余额 >= 还款金额
   - 更新钱包余额 = 原余额 - 还款金额
   - 更新已使用透支 = 原透支 - 还款金额
3. 如果使用第三方支付：
   - 跳转到第三方支付流程（前端暂未实现）
4. 创建交易流水记录（类型：repay）

**错误响应**:
```json
{
  "success": false,
  "message": "钱包余额不足" // 或其他错误信息
}
```

**接口路径**: `POST /api/wallet/pay`

**功能说明**: 使用钱包余额支付订单

**前端调用位置**:
- `elmclient/src/views/Payment.vue` 第165行

**请求头**:
```
Authorization: Bearer {token}
Content-Type: application/json
```

**请求体**:
```json
{
  "orderId": 12345,  // 订单ID
  "amount": 100.00  // 支付金额（元）
}
```

**响应格式**:
```json
{
  "success": true,
  "data": {
    "transactionId": 12348,
    "orderId": 12345,
    "payAmount": 100.00,
    "finalBalance": 900.00  // 支付后的余额
  },
```

**业务逻辑**:

2. 验证钱包余额 >= 支付金额（如果余额不足，可以使用透支额度）

   - 更新已使用透支
4. 扣除钱包余额（或使用透支）
5. 更新订单状态为已支付
6. 创建交易流水记录（类型：payment）
7. 如果是支付给商家，需要创建商家的收款流水（类型：received_payment）

**错误响应**:
```json
{
  "success": false,
  "message": "余额不足或账户异常" // 或其他错误信息
}
```

## 数据模型

### 钱包表（Wallet）

```sql
CREATE TABLE wallet (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL UNIQUE,
    balance DECIMAL(10, 2) DEFAULT 0.00 COMMENT '账户余额',
    is_vip BOOLEAN DEFAULT FALSE COMMENT '是否为VIP',
    vip_level INT DEFAULT 0 COMMENT 'VIP等级：0-普通，1-VIP1，2-VIP2，3-VIP3',
    overdraft_limit DECIMAL(10, 2) DEFAULT 0.00 COMMENT '可透支总额度',
    used_overdraft DECIMAL(10, 2) DEFAULT 0.00 COMMENT '已使用透支金额',
    frozen_amount DECIMAL(10, 2) DEFAULT 0.00 COMMENT '冻结金额',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id)
);
```

### 交易流水表（WalletTransaction）

```sql
CREATE TABLE wallet_transaction (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    transaction_time DATETIME NOT NULL COMMENT '交易时间',
    amount DECIMAL(10, 2) NOT NULL COMMENT '交易金额（正数收入，负数支出）',
    transaction_type VARCHAR(50) NOT NULL COMMENT '交易类型：recharge/withdraw/payment/received/overdraft/repay/reward/fee',
    reason VARCHAR(255) COMMENT '交易原因',
    in_account BIGINT COMMENT '入账钱包账号（用户ID）',
    out_account BIGINT COMMENT '出账钱包账号（用户ID）',
    counterparty_account VARCHAR(255) COMMENT '对方账户信息（用于显示）',
    order_id BIGINT COMMENT '关联订单ID（如果是支付）',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_id (in_account, out_account),
    INDEX idx_transaction_time (transaction_time),
    INDEX idx_transaction_type (transaction_type)
);
```

### 规则配置表（WalletRule，可选）

```sql
CREATE TABLE wallet_rule (
    id INT PRIMARY KEY AUTO_INCREMENT,
    rule_key VARCHAR(50) NOT NULL UNIQUE COMMENT '规则键：recharge_reward_rate/withdraw_fee_rate',
    rule_value DECIMAL(5, 4) NOT NULL COMMENT '规则值（小数）',
    rules_text TEXT COMMENT '规则详细文本（HTML格式）',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

## 错误处理

### 统一错误响应格式

```json
{
  "success": false,
  "message": "错误信息描述",
  "code": "ERROR_CODE"  // 可选，错误代码
}
```

### 常见错误码

- `WALLET_NOT_FOUND`: 钱包不存在
- `INSUFFICIENT_BALANCE`: 余额不足
- `INVALID_AMOUNT`: 金额无效
- `INVALID_VIP_LEVEL`: VIP等级无效
- `OVERDRAFT_LIMIT_EXCEEDED`: 超出透支额度
- `ORDER_NOT_FOUND`: 订单不存在
- `ORDER_ALREADY_PAID`: 订单已支付

### HTTP状态码

- `200`: 请求成功
- `400`: 请求参数错误
- `401`: 未授权（token无效或过期）
- `404`: 资源不存在（如钱包不存在）
- `500`: 服务器内部错误

## 注意事项

### 1. 事务处理

以下操作必须使用数据库事务保证数据一致性：
- 充值（更新余额 + 创建流水）
- 提现（更新余额 + 创建流水）
- 支付（更新余额 + 更新订单状态 + 创建流水）
- 还款（更新余额 + 更新透支金额 + 创建流水）

### 2. 并发控制

钱包余额更新需要使用乐观锁或悲观锁防止并发问题：
```java
// 示例：使用版本号乐观锁
UPDATE wallet 
SET balance = balance + ?, version = version + 1 
WHERE user_id = ? AND version = ?
```

### 3. 透支逻辑

- 支付时如果余额不足，自动使用透支额度
- 透支金额需要记录在`usedOverdraft`字段
- 透支需要计算利息（根据需求文档，如果未在规定时间内还款）

### 4. 冻结金额

- 支付给商家后，资金可能需要冻结直到用户确认收货
- 冻结金额记录在`frozenAmount`字段
- 确认收货后，将冻结金额转移到商家账户

### 5. 充值奖励扣除

- 提现时需要扣除之前获得的充值奖励
- 需要记录用户的充值奖励历史，按FIFO或LIFO原则扣除

### 6. 消息通知

- 透支贷款等重要信息需要通过WebSocket或消息系统通知用户
- 使用现有的消息通知接口（`/api/notifications`）

### 7. 前端代码位置汇总

| 功能 | 文件路径 | 行号范围 |
|-----|---------|---------|
| 钱包主页面 | `elmclient/src/views/Wallet.vue` | 已启用后端接口，模拟逻辑以注释保留 |
| 交易明细页 | `elmclient/src/views/WalletTransactions.vue` | 已启用后端接口 |
| 支付页面（钱包支付） | `elmclient/src/views/Payment.vue` | 已启用后端接口，包含“开通钱包”弹窗 |
| 我的页面（钱包入口） | `elmclient/src/views/MyInformation.vue` | 钱包入口与说明 |
| 路由配置 | `elmclient/src/router/index.js` | 26-27, 226-237 |
